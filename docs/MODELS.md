# 모델 선택

**작업 배정 예시**이며, 비교 벤치마크나 품질 보장이 아닙니다. 모델 접근은 제품·계정·조직 설정에 따르며 이 저장소가 제공하지 않습니다.

## 역할 예시

| 모델·공식 문서 | 모델 ID | 작업 범위 | 배정 조건 |
|---|---|---|---|
| [Sol 6.1](https://developers.openai.com/api/docs/models/gpt-6.1-sol) | `gpt-6.1-sol` | 요구사항·계획·핵심 구현·복잡한 오류·최종 검토 | 목표·제약·완료 기준을 함께 전달 |
| [Luna 6](https://developers.openai.com/api/docs/models/gpt-6-luna) | `gpt-6-luna` | 작은 함수·입력 검사·문구·스타일 수정 | 설계·입출력·검사 방법 지정, 범위 확대 시 주 담당에게 반환 |
| [Terra 5.6](https://developers.openai.com/api/docs/models/gpt-5.6-terra) | `gpt-5.6-terra` | 작은 일반 모듈·요구사항 대조·보조 검토 | 요구와 근거 지정, 문서·UX 특화 모델로 가정하지 않음 |
| [Sol 6.0](https://developers.openai.com/api/docs/models/gpt-6-sol) | `gpt-6-sol` | 대체 구현·누락·회귀 검토 | 재현 가능한 문제와 필요한 수정으로 범위 제한 |

Terra 5.6과 Terra 6.1은 다릅니다. 실제 선택 항목의 ID와 공식 제공 조건을 확인합니다.

## 작업 분담

**Sol 6.1 구현 → 필요 시 Luna 6 수정 → Sol 6.1 검증**으로 시작합니다. 추가 검토는 선택 사항입니다. 입력·완료 조건이 분명하고 수정 파일이 겹치지 않는 작업을 분리합니다.

| 전달 항목 | 예시 |
|---|---|
| 목표·범위 | 빈 검색어의 조회 요청 차단, 입력 함수와 관련 테스트 수정 |
| 제약 | 기존 API·화면 동작 유지, 패키지 추가 없음 |
| 완료·보고 기준 | 빈 값·공백·정상 값 확인, 변경점·검사 결과·미확인 사항 보고 |

## 설정·검증

모델은 선택 화면이나 지원되는 CLI 명령 `/status`·`/model`로 확인합니다. 전환 시 결정 사항·수정 파일·남은 작업을 전달합니다.

추론 강도는 문제·검증 난도에 맞춥니다. 높이면 시간·토큰 사용이 늘 수 있습니다. 비용·지연·제공 범위는 변할 수 있습니다. [Codex 모델 안내](https://learn.chatgpt.com/docs/models?surface=cli)

모델 간 검토에도 같은 오해가 남을 수 있습니다. 필수조건을 대조하고 테스트·재계산·직접 확인으로 검증합니다.
