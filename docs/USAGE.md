# 사용 안내

[README](../README.md) · [스킬 목록](CATALOG.md) · [출처·라이선스](../SOURCES.md)

## 1. 저장소 준비

```bash
git clone https://github.com/parkhyunjae01/ai-work-skills.git
cd ai-work-skills
```

AI 도구에는 전체 URL 또는 `parkhyunjae01/ai-work-skills`를 전달합니다. 검색 기능이 없는 환경에서도 공개 GitHub 다운로드가 허용된다면 알려진 주소로 접근할 수 있습니다. 네트워크와 명령 실행 권한은 사용하는 환경에 따라 확인해야 합니다.

## 2. 스킬 선택

작업의 입력·결과물·완료 기준을 확인한 뒤 필요한 스킬 2~3개를 선택합니다. 세부 역할과 의존성은 [스킬 목록](CATALOG.md)에 정리되어 있습니다.

`catalog.json`은 후보별 포함 상태를 구분합니다.

| 필드 | 의미 |
|---|---|
| `name` | 스킬 이름 |
| `status: bundled` | 원본과 참조 파일을 저장소에 포함 |
| `status: authored` | 이 저장소에서 직접 작성한 스킬. 루트 MIT 라이선스 적용 |
| `status: link-only` | 원본 링크만 제공. 자동 설치 대상에서 제외 |
| `local_path` | 포함된 스킬의 `SKILL.md` 경로 |
| `template_path` | 직접 작성한 스킬이 사용하는 빈 출력 양식 |
| `upstream_url` | 공개 원본 주소 |
| `reason` | 링크만 제공하는 사유 |

기본 후보는 원본 포함 24개, 직접 작성 1개, 링크 제공 8개입니다. 연결된 스킬을 추가로 보관하므로 실제 `SKILL.md` 파일 수는 후보 수와 다를 수 있습니다.

## 3. 지침 적용

선택한 `SKILL.md`와 연결된 참조 파일을 읽고 현재 작업에 적용합니다. 다운로드만으로 모든 스킬이 활성화되거나 `/skills`에 등록되지는 않습니다.

> 현재 작업의 요구사항을 먼저 분석해줘. 이 저장소의 catalog.json에서 필요한 스킬 2~3개를 선택하고 local_path의 SKILL.md와 연결된 참조 파일을 읽어 적용해줘. link-only 항목은 자동 설치하지 말고, 사용할 도구와 현재 환경의 제약을 확인해줘.

`vendor/`의 원래 폴더 구조를 유지합니다. 예를 들어 업무 스킬의 `../../CONNECTORS.md`는 스킬 폴더 밖의 파일을 참조합니다. 스킬만 별도 폴더에 복사하면 이 경로가 끊길 수 있습니다.

전역 등록이 필요한 경우 사용 중인 Codex 버전의 설치 방법과 참조 경로 처리 방식을 별도로 확인합니다. 이 저장소는 계정·모델·권한 설정을 자동으로 변경하지 않습니다.

## 4. 실행 환경 확인

| 항목 | 확인 내용 |
|---|---|
| 런타임·라이브러리 | 원본 스크립트가 요구하는 Python·Node.js·패키지 |
| 호스트 호환성 | Claude 전용 명령, 등록 에이전트, Codex 지원 방식 |
| 계정·연결 | 플러그인 인증, API 키, 서비스 접근 권한 |
| 데이터 처리 | 외부 요청에 포함되는 정보와 저장 위치 |
| 작업 규정 | 사용 가능한 모델·도구·자동화 범위 |

공개 원본의 도구가 현재 환경에도 제공된다고 가정하지 않습니다. 원본 지침보다 사용자 요청과 해당 환경의 규정을 우선합니다. 모든 부속 코드의 보안 감사나 모든 환경의 동작 검증을 완료한 모음은 아니므로, 스크립트 실행 전에 필요한 도구와 동작을 확인해야 합니다.

서비스별 연결 조건은 [플러그인·MCP 안내](PLUGINS.md)를 참고하세요.

## 5. 무결성 검사

```bash
python3 scripts/verify_bundle.py
```

Python 3.9 이상이 필요합니다. 검사 대상은 카탈로그·원본 파일 해시·참조 문서이며, 원본 스크립트를 실행하거나 네트워크에 연결하지 않습니다. 성공 메시지는 파일 보관 상태를 확인한 결과로, 스킬의 실행 품질을 보증하지 않습니다.
