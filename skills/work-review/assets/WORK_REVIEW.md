## 한눈에 보기

- **만든 것** — 누구의 어떤 문제를 해결했는지 한 문장.
- **확인한 결과** — 실제로 확인한 기능·효과와 확인 범위 한 문장.
- **남은 문제** — 가장 중요한 미해결·미검증 항목과 다음 행동 한 문장.

갱신일 · 〈시점〉 / 기준 결과물 · 〈버전 또는 파일 상태〉

## 1. 사용 방법과 동작 흐름

**완료 기준** — 어떤 요구사항을 충족해야 하는지와 그 출처를 적습니다.

전제 조건과 작업 위치를 짧게 적습니다. 사용 안내가 별도로 있으면 그 파일로 연결합니다.

1. 실행에 필요한 명령 또는 파일을 적습니다. 명령은 별도 코드 블록에 둡니다.
2. 사용자 역할과 첫 동작, 대표 입력을 적습니다.
3. 기대 결과와 어디에서 확인하는지 적습니다.

**동작 흐름** — 입력 → 주요 처리 → 결과를 한 줄로 연결합니다. 필요한 구성요소·함수는 근거에 연결합니다.

**확인 범위** — 실제로 끝까지 실행한 절차와 코드로만 확인한 절차를 구분합니다. 잘못된 입력의 처리나 확인된 복구 방법이 중요하면 여기에 적습니다.

근거 · 실제 요구사항과 관련 파일을 짧은 이름의 상대 경로 링크로 연결합니다.

## 2. 중요한 선택

### 〈선택한 방법이 드러나는 제목〉

**결론** — 무엇을 선택했는지 한 문장.

- **이유** — 실제 요구사항·제약과 연결합니다. 당시 이유가 기록되지 않았다면 `선택 이유 미확인`으로 적습니다.
- **검토한 대안** — 실제로 검토한 방법과 채택하지 않은 이유를 적습니다. 사후에 떠올린 대안은 구분합니다.
- **얻은 점과 감수한 점** — 효과와 함께 달라진 비용·자원을 적습니다. 수치가 있으면 지표 정의·기준안·비교 기간도 밝힙니다.

근거 · 관련 결정 기록과 파일을 연결합니다. 다른 중요한 선택이 있으면 소제목을 추가합니다.

## 3. 오류와 해결 과정

### 〈사용자에게 나타난 실제 증상〉

**현재 상태** — 수정 여부와 재검증 범위를 한 문장으로 적습니다. 남은 문제가 있으면 함께 밝힙니다.

**증상과 재현**

누가 어떤 입력·행동을 했을 때 무엇을 기대했으며, 실제로 무엇이 발생했는지 적습니다.

**원인과 근거**

어떤 관찰로 원인을 좁혔는지 적습니다. 확인한 원인과 가설을 구분하고, 기각한 후보가 있으면 근거를 남깁니다.

**수정한 내용**

어느 파일·함수를 어떻게 바꿨는지와 그 이유를 적습니다. 실패한 수정 시도가 있으면 결과도 보존합니다.

**다시 확인한 결과**

같은 사례를 어떤 절차로 다시 확인했고 어디까지 성공했는지 적습니다. 단위 테스트 통과와 실제 사용자 화면 확인을 구분합니다.

근거 · 수정 파일과 검증 기록을 연결합니다. 중요한 오류마다 이 구조를 반복합니다. 확인 가능한 오류 기록이 없으면 그 사실만 적습니다.

## 4. 검증 결과

위 사례에서 설명하지 않은 중요한 확인 결과를 짧게 정리합니다. 자세한 명령·입력·관찰 결과는 표 아래에 적거나 실제 기록으로 연결합니다.

| 확인 항목 | 상태·확인 범위 | 근거 |
|---|---|---|
| 실제 확인 항목 | 관찰한 상태 | 관련 기록 위치 |

`계획`·`미실행`·`실행 실패`·`통과`·`미확인`을 구분합니다. 이전 성공 후 파일이 변경됐다면 최종 변경 후 재검증 여부를 밝힙니다.

## 5. AI와 본인이 한 일

### 〈중요한 작업명〉

- **요청한 목표** — AI에 맡긴 범위를 적습니다.
- **AI가 한 일** — 실제 제안·작성 내용을 적습니다.
- **본인의 판단** — 채택·수정·기각한 내용과 이유를 적습니다. 본인 확인 기록이 없으면 `본인 확인 필요`로 남깁니다.
- **확인 결과** — 관찰한 결과를 적습니다. 앞서 설명한 사례는 해당 절로 연결합니다.

근거 · 해당 작업 기록과 결과물을 연결합니다.

## 6. 다음에 할 일

남은 한계·실패 가능성 중 영향이 큰 순서로 적습니다. 각 항목은 다음 행동과 확인 방법까지 한두 문장으로 연결합니다.
